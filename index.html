The problem

Crypto builders pay RPC and API providers every month for an uptime promise. When the endpoint goes down, bots miss trades and dApps break, but the SLA credit only comes if you open a ticket, argue and wait. Most teams never claim it. The provider is the one who decides if the outage "counted".

FACT

The proof is already public

Providers publish incidents on their status pages. Nobody turns that into an automatic refund.

GAP

Reading a status page is subjective

Which incident hit your component? Outage or "degraded"? Scheduled maintenance? A normal smart contract can't judge this.

FIX

GenLayer validators judge, code pays

Validators measure downtime and must agree on the same SLA tier. Fixed credit table decides the money.

How it works

01 · CUSTOMER

Create a plan

Provider wallet, component, status page URL, SLA % and period. Fee is locked in this plan's own escrow.

02 · PROVIDER

Accept (+ bond)

Provider accepts the terms, optionally posts a bond. The period starts. No accept → customer cancels and gets the fee back.

03 · CUSTOMER

Report hidden outage

If the status page hides an outage, add one public evidence link (third-party monitor). Validators weigh it.

04 · ANYONE

Settle

After the period, validators read the page and agree on the tier. Contract pays both sides in the same transaction.
